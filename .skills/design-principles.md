# Skill: Design Principles

## Purpose
Provide foundational judgment for product and interface design.

## Principles
- **Purpose**: every feature/screen should have a clear reason and user outcome.
- **Agency**: people should understand what they can do, what is happening, and how to recover.
- **Familiarity**: use established mental models unless departure provides meaningful value.
- **Simplicity**: remove unnecessary complexity without hiding important information.
- **Hierarchy**: structure and visual weight should communicate importance and relationships.
- **Consistency**: similar things should behave similarly; differences should be meaningful.
- **Feedback**: consequential actions should produce understandable feedback.
- **Flexibility**: support relevant contexts, devices, input methods, and needs.
- **Trust**: be transparent about consequential actions, permissions, data, and failures.
- **Craft**: details matter when they improve comprehension, confidence, usability, or quality.
- **Delight**: delight should reinforce purpose rather than compete with it.

## Decision test
1. What user problem does this solve?
2. What does it clarify?
3. What cognitive cost does it introduce?
4. Does it match established patterns?
5. What happens on error?
6. Is it accessible?
7. Is it secure?
8. Is the value worth the complexity?

## Source basis
Synthesized from Nielsen Norman Group usability heuristics, W3C accessibility principles, and Apple Human Interface Guidelines. These sources frame principles as contextual decision tools rather than rigid laws.
