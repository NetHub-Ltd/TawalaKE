# Skill: Forms and Data-Dense Interfaces

## Forms
For every field:
- Explain what is needed.
- Use user terminology.
- Label clearly.
- Group related inputs.
- Set defaults only when safe.
- Validate at useful moments without noisy interruption.
- Preserve entered data after errors.
- Explain errors at the point of action.
- Distinguish required from optional.
- Make the primary action obvious.

## Tables
- Prioritize information users actually compare.
- Use understandable headers.
- Preserve row context.
- Support sorting/filtering where useful.
- Never encode critical state through color alone.
- Make row actions discoverable.
- Design loading/empty/error/partial states.

## Dashboards
A dashboard should answer specific questions, not merely display available metrics.

For each metric ask:
- Why does the user need this?
- What decision does it support?
- What action follows?
- What context is needed?

Data density should follow task requirements, not a generic preference for "clean" UI.
